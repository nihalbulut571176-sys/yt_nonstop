# Системные инструкции для пайплайна `SRT -> визуал -> монтаж`

## Принцип работы

1. Всегда сначала делаем `SRT` по реальному аудио.
2. Тайминги берутся только из аудио, а не из текста сценария.
3. Только после готового `SRT` делаются визуальные промты.
4. Каждый визуал должен быть привязан к конкретному таймкоду и функции в драматургии.
5. Если смысловой блок длиннее 5 секунд, он разбивается на несколько кадров или микро-сцен.

## Правила для субтитров

1. `SRT` нужен прежде всего как монтажный каркас.
2. Приоритет номер один: точные тайминги входа и выхода реплик.
3. Допустима текстовая нормализация распознавания, если тайминг остается верным.
4. Если ASR ошибся в словах, но правильно поймал паузу, правим текст, а не тайминг.
5. Если фраза длинная, ее лучше делить по естественным паузам диктора.

## Правила для визуальных промтов

1. Промт должен описывать не “картинку по слову”, а смысл сцены.
2. Нельзя скатываться в банальность вида “логотип Telegram + телефон + красивый фон”.
3. Если речь про архитектуру шифрования, показываем:
   распределенную инфраструктуру, фрагментацию данных, узлы, юрисдикции, цифровую фортификацию, слепую математику.
4. Если речь про криминал, показываем:
   процессы, цепочки, интерфейсы, безличность системы, логистику, дистанцию между боссом и последствиями.
5. Если речь про свободу и слежку, показываем:
   контроль, наблюдение, экраны, сетевые узлы, ощущение вторжения в личное пространство.
6. У каждого промта должна быть драматургическая функция:
   крючок, усиление тревоги, объяснение, поворот, масштабирование, моральный удар.
7. Для длинных блоков делать последовательность:
   establishing shot -> detail shot -> reveal shot -> consequence shot.

## Единый визуальный стиль

1. Тон: investigative thriller, grounded, cinematic, realistic.
2. Не использовать случайный cyberpunk-neon без сюжетного смысла.
3. Не использовать буквальный “матриц-подобный” зеленый код, если сцена не про стереотипы.
4. Свет и цвет подчиняются смыслу:
   холодные тона для тревоги и наблюдения, теплые роскошные тона для власти и безнаказанности, нейтрально-жесткие для аналитических объяснений.
5. Картинка должна чувствоваться как дорогой документальный YouTube-essay, а не как stock footage collage.

## Что обязательно указывать в промте

1. Кто или что в центре кадра.
2. Где это происходит.
3. Что происходит в моменте.
4. Какой конфликт или подтекст в кадре.
5. Тип кадра или камера:
   wide shot, medium shot, close-up, overhead, macro detail, surveillance angle.
6. Свет, атмосфера и фактура.
7. Ограничения:
   no text, no watermarks, no UI labels, no generic app ad aesthetic.

## Правила для промтов оживления

1. Анимация должна усиливать смысл, а не просто “двигать картинку”.
2. Для тревоги подходят:
   slow push-in, subtle handheld shake, flickering practical lights, moving shadows, drifting fog.
3. Для цифровой инфраструктуры подходят:
   flowing packet streams, node activation, jurisdiction map pulses, parallax layers, data fragmentation.
4. Для элитного криминального мира подходят:
   slow dolly, heat shimmer, glass reflections, minimal body movement, controlled luxury.
5. Для первой минуты ролика анимация обязана удерживать внимание без визуального шума.

## Красные флаги

1. Не делать “просто красивое здание” там, где речь про архитектуру приложения.
2. Не делать “хакер в капюшоне” по умолчанию.
3. Не делать одинаковые кадры “человек держит телефон” несколько раз подряд.
4. Не делать прямолинейную иллюстрацию там, где нужен концептуальный кадр.
5. Не терять общий тезис ролика:
   одна и та же технология одновременно защищает свободу и масштабирует зло.
